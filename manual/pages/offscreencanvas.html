OffscreenCanvas

OffscreenCanvas 是一个相对较新的浏览器功能，目前仅在 Chrome 中可用，但显然会在其他浏览器中推出。OffscreenCanvas 允许 web worker 渲染到 canvas。这是一种将繁重工作（如渲染复杂的 3D 场景）卸载到 web worker 的方法，以免降低浏览器的响应速度。这也意味着数据在 worker 中加载和解析，因此页面加载时可能会减少卡顿。

开始使用它相当简单。让我们将来自 响应性文章 的 3 个旋转立方体示例移植过来。

通常，工作线程会将它们的代码分离到另一个脚本文件中，而本网站上的大多数示例则将脚本嵌入到它们所在页面的 HTML 文件中。

在我们的例子中，我们将创建一个名为 offscreencanvas-cubes.js 的文件，并将 响应式示例 中的所有 JavaScript 复制到该文件中。然后，我们将进行所需的更改以使其能够在工作线程中运行。

function main() {
  const canvas = document.querySelector('#c');
  const offscreen = canvas.transferControlToOffscreen();

  worker.postMessage({type: 'main', canvas: offscreen}, [offscreen]);
}
main();

需要注意的是，工人无法访问 DOM。他们既不能查看 HTML 元素，也不能接收鼠标事件或键盘事件。他们通常唯一能做的就是响应发送给他们的消息，并向页面发送消息。

要向工人发送消息，我们称之为worker.postMessage并传入1或2个参数。第一个参数是一个JavaScript对象，它将是克隆的并发送给工作者。第二个参数是一个可选的对象数组，它们是我们想要的第一个对象的一部分已转移给工人。这些对象不会被克隆。相反，它们将被已转移并且将在主页上消失。'消失'可能是错误的描述，更准确的是它们被去势了。只有某些类型的对象可以被转移，而不是克隆。它们包括 OffscreenCanvas，所以一旦被转移，主页上的 offscreen 对象就无用了。

工人从他们的 onmessage 处理程序接收消息。我们传递给 postMessage 的对象会在传递给工人的 event.data 处理程序的 onmessage 上到达。上面的代码在传递给 worker 的对象中声明了一个 type: 'main'。这个对象对浏览器没有任何意义。它完全是供我们自己使用的。我们将创建一个根据 type 调用 worker 中不同函数的处理程序。然后我们可以根据需要添加函数，并轻松从主页面调用它们。

const handlers = {
  main,
};

self.onmessage = function(e) {
  const fn = handlers[e.data.type];
  if (typeof fn !== 'function') {
    throw new Error('no handler for type: ' + e.data.type);
  }
  fn(e.data);
};

你可以看到，上面我们只是根据 type 查找处理程序，并传递它从主页面发送的 data。

class PickHelper {
  constructor() {
    this.raycaster = new THREE.Raycaster();
    this.pickedObject = null;
    this.pickedObjectSavedColor = 0;
  }
  pick(normalizedPosition, scene, camera, time) {
    // restore the color if there is a picked object
    if (this.pickedObject) {
      this.pickedObject.material.emissive.setHex(this.pickedObjectSavedColor);
      this.pickedObject = undefined;
    }

    // cast a ray through the frustum
    this.raycaster.setFromCamera(normalizedPosition, camera);
    // get the list of objects the ray intersected
    const intersectedObjects = this.raycaster.intersectObjects(scene.children);
    if (intersectedObjects.length) {
      // pick the first object. It's the closest one
      this.pickedObject = intersectedObjects[0].object;
      // save its color
      this.pickedObjectSavedColor = this.pickedObject.material.emissive.getHex();
      // set its emissive color to flashing red/yellow
      this.pickedObject.material.emissive.setHex((time * 8) % 2 > 1 ? 0xFFFF00 : 0xFF0000);
    }
  }
}

让我们再进一步，加入 OrbitControls。 这会稍微复杂一些。OrbitControls 广泛使用 DOM 来检查鼠标、触摸事件和键盘。

与我们迄今为止的代码不同，我们实际上不能在不重写所有 OrbitControls 代码的情况下使用全局 state 对象。OrbitControls 接受一个 HTMLElement，并将它们使用的绝大多数 DOM 事件附加到该对象上。也许我们可以传入我们自己的对象，该对象具有与 DOM 元素相同的 API 接口。我们只需要支持 OrbitControls 所需的功能。

浏览 OrbitControls 源代码，看起来我们需要处理以下事件。

  • contextmenu
  • pointerdown
  • pointermove
  • pointerup
  • touchstart
  • touchmove
  • touchend
  • wheel
  • keydown

对于指针事件，我们需要 ctrlKey、metaKey、shiftKey、button、pointerType、clientX、clientY、pageX 和 pageY 属性。

对于按键按下事件，我们需要 ctrlKey、metaKey、shiftKey 和 keyCode 属性。

对于滚轮事件，我们只需要 deltaY 属性。

而对于触摸事件，我们只需要从 pageX 属性中使用 pageY 和 touches。

所以，让我们创建一个代理对象对。一部分将在主页面运行，获取所有这些事件，并将相关属性值传递给 worker。另一部分将在 worker 中运行，接收这些事件，并使用与原始 DOM 事件结构相同的事件传递它们，这样 OrbitControls 就无法区分差异。

这是 worker 部分的代码。

import {EventDispatcher} from 'three';

class ElementProxyReceiver extends EventDispatcher {
  constructor() {
    super();
  }
  handleEvent(data) {
    this.dispatchEvent(data);
  }
}

它所做的只是接收到消息时进行分发。它继承自 EventDispatcher，该类提供了像 addEventListener 和 removeEventListener 这样的方法，就像 DOM 元素一样，所以如果我们将它传给 OrbitControls，它应该可以工作。

ElementProxyReceiver 处理 1 个元素。在我们的例子中我们只需要一个，但最好未雨绸缪，所以我们来创建一个管理器来管理多个元素。

class ProxyManager {
  constructor() {
    this.targets = {};
    this.handleEvent = this.handleEvent.bind(this);
  }
  makeProxy(data) {
    const {id} = data;
    const proxy = new ElementProxyReceiver();
    this.targets[id] = proxy;
  }
  getProxy(id) {
    return this.targets[id];
  }
  handleEvent(data) {
    this.targets[data.id].handleEvent(data.data);
  }
}

我们可以创建一个 ProxyManager 的实例，并用一个 id 调用它的 makeProxy 方法，这将创建一个 ElementProxyReceiver，用于响应具有该 id 的消息。

let nextProxyId = 0;
class ElementProxy {
  constructor(element, worker, eventHandlers) {
    this.id = nextProxyId++;
    this.worker = worker;
    const sendEvent = (data) => {
      this.worker.postMessage({
        type: 'event',
        id: this.id,
        data,
      });
    };

    // register an id
    worker.postMessage({
      type: 'makeProxy',
      id: this.id,
    });
    for (const [eventName, handler] of Object.entries(eventHandlers)) {
      element.addEventListener(eventName, function(event) {
        handler(event, sendEvent);
      });
    }
  }
}

ElementProxy 接收我们想要代理其事件的元素。然后，它通过选择一个 ID 并通过我们之前设置的 makeProxy 消息发送给 worker 来注册该 ID。worker 将创建一个 ElementProxyReceiver 并将其注册到该 ID。

然后我们有一个事件处理程序对象要注册。这样我们就可以只传递我们想要转发给工作线程的这些事件的处理程序。

function copyProperties(src, properties, dst) {
  for (const name of properties) {
      dst[name] = src[name];
  }
}

function makeSendPropertiesHandler(properties) {
  return function sendProperties(event, sendFn) {
    const data = {type: event.type};
    copyProperties(event, properties, data);
    sendFn(data);
  };
}

function touchEventHandler(event, sendFn) {
  // preventDefault() fixes mousemove, mouseup and mousedown 
  // firing when doing a simple touchup touchdown
  // Happens only at offscreen canvas
  event.preventDefault(); 
  const touches = [];
  const data = {type: event.type, touches};
  for (let i = 0; i < event.touches.length; ++i) {
    const touch = event.touches[i];
    touches.push({
      pageX: touch.pageX,
      pageY: touch.pageY,
      clientX: touch.clientX,
      clientY: touch.clientY,
    });
  }
  sendFn(data);
}
