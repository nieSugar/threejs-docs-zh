Cleanup

Three.js 应用程序通常会使用大量内存。 3D模型 所有顶点的内存可能为 1 到 20 兆。 一个模型可能会使用许多纹理，即使它们是 压缩成 jpg 文件，必须对其进行扩展 以未压缩的形式使用。每个 1024x1024 纹理需要 4 到 6meg 内存。

大多数 Three.js 应用程序在初始化时加载资源，并且 然后永远使用这些资源，直到页面被 关闭。但是，如果您想加载和更改资源怎么办 随着时间的推移？

与大多数 JavaScript 不同， Three.js 不能自动 清理这些资源。浏览器会清理它们 如果您切换页面，则向上，但否则由您决定 来管理他们。这是WebGL如何设计的问题 所以 Three.js 没有办法只能传递 释放资源的责任归还给您。

您通过调用 dispose 函数释放了 Three.js 资源 纹理， 几何图形，以及 材质.

您可以手动执行此操作。一开始你可能会创建 其中一些资源

const boxGeometry = new THREE.BoxGeometry(...);
const boxTexture = textureLoader.load(...);
const boxMaterial = new THREE.MeshPhongMaterial({map: texture});

，然后当您使用完它们后，您将释放它们

boxGeometry.dispose();
boxTexture.dispose();
boxMaterial.dispose();

随着您使用越来越多的资源，这些资源会获得越来越多的资源 更乏味。

为了帮助消除一些乏味，让我们创建一个类来跟踪 资源。然后我们会要求该类进行清理 对于我们来说.

这是此类的第一次

class ResourceTracker {
  constructor() {
    this.resources = new Set();
  }
  track(resource) {
    if (resource.dispose) {
      this.resources.add(resource);
    }
    return resource;
  }
  untrack(resource) {
    this.resources.delete(resource);
  }
  dispose() {
    for (const resource of this.resources) {
      resource.dispose();
    }
    this.resources.clear();
  }
}

const gltfLoader = new GLTFLoader();
function loadGLTF(url) {
  return new Promise((resolve, reject) => {
    gltfLoader.load(url, resolve, undefined, reject);
  });
}

function waitSeconds(seconds = 0) {
  return new Promise(resolve => setTimeout(resolve, seconds * 1000));
}

const fileURLs = [
  'resources/models/cartoon_lowpoly_small_city_free_pack/scene.gltf',
  'resources/models/3dbustchallange_submission/scene.gltf',
  'resources/models/mountain_landscape/scene.gltf',
  'resources/models/simple_house_scene/scene.gltf',
];

async function loadFiles() {
  for (;;) {
    for (const url of fileURLs) {
      const resMgr = new ResourceTracker();
      const track = resMgr.track.bind(resMgr);
      const gltf = await loadGLTF(url);
      const root = track(gltf.scene);
      scene.add(root);

      // compute the box that contains all the stuff
      // from root and below
      const box = new THREE.Box3().setFromObject(root);

      const boxSize = box.getSize(new THREE.Vector3()).length();
      const boxCenter = box.getCenter(new THREE.Vector3());

      // set the camera to frame the box
      frameArea(boxSize * 1.1, boxSize, boxCenter, camera);

      await waitSeconds(2);
      renderer.render(scene, camera);

      resMgr.dispose();

      await waitSeconds(1);

    }
  }
}

有关代码的一些注释。

如果我们想一次加载 2 个或更多文件并释放它们 每当我们为每个文件使用一个 ResourceTracker 时。

上面我们仅在加载后立即跟踪 gltf.scene 。 基于我们当前的 ResourceTracker 实现 将跟踪刚刚加载的所有资源。如果我们添加更多 场景中的事物我们需要决定是否跟踪它们。

例如，假设我们加载角色后放置了一个工具 通过使该工具成为他们手中的子工具而在他们手中。因为它是 该工具将不会被释放。我经常猜测 这就是我们想要的。

这提出了一个观点。最初当我第一次写ResourceTracker时 上面我遍历了 dispose 方法而不是 track 内部的所有内容。 后来我才把这个工具当作上面手提箱的孩子 很明显，准确跟踪 track 中要释放的内容更重要 灵活并且可以说更正确，因为我们可以跟踪加载的内容 从文件中删除，而不是稍后释放场景图的状态。

老实说，我对 ResourceTracker 并不是 100% 满意。做事是这样的 这种方式在 3D 引擎中并不常见。我们不应该猜测什么 资源已加载，我们应该知道。要是有three.js就好了 更改，以便所有文件加载器返回一些标准对象 对加载的所有资源的引用。至少目前来说， Three.js 在加载场景时不会给我们任何更多信息，所以这个 解决方案似乎有效。
