原始体

本文是有关 Three.js 的系列文章中的一篇。 第一篇文章是关于基础知识。 如果您还没有读过，您可能想从这里开始。

Three.js 有大量的原始体。原始体通常是运行时生成的 3D 形状，并且带有一堆参数。

通常会使用基本图形（primitives）来表示一些事物，比如用球体表示地球仪，或用一堆盒子绘制三维图表。在实验和入门三维设计时尤其常用基本图形。对于大多数三维应用来说，更常见的做法是让艺术家在三维建模程序中制作三维模型，例如Blender、Maya或Cinema 4D。在本系列后面，我们会讲述如何从多个三维建模程序中创建和加载数据。现在，让我们先介绍一些可用的基本图形。

让我们添加一个函数，addObject，该函数接收 x, y 位置和一个 Object3D 并将对象添加到场景中。

const objects = [];
const spread = 15;

function addObject(x, y, obj) {
  obj.position.x = x * spread;
  obj.position.y = y * spread;

  scene.add(obj);
  objects.push(obj);
}

让我们也创建一个函数来生成随机颜色的材质。我们将使用 Color 的一个功能，该功能允许你根据色相、饱和度和亮度设置颜色。

hue 在颜色轮上从 0 到 1 变化，红色为 0，绿色为 0.33，蓝色为 0.66。saturation 从 0 到 1 变化，0 表示无色，1 表示最饱和。luminance 从 0 到 1 变化，0 为黑色，1 为白色，0.5 为颜色的最大量。换句话说，当 luminance 从 0.0 变化到 0.5 时，颜色将从黑色变为 hue。从 0.5 到 1.0，颜色将从 hue 变化到白色。

function createMaterial() {
  const material = new THREE.MeshPhongMaterial({
    side: THREE.DoubleSide,
  });

  const hue = Math.random();
  const saturation = 1;
  const luminance = .5;
  material.color.setHSL(hue, saturation, luminance);

  return material;
}

我们还将 side: THREE.DoubleSide 传递给了材质。这告诉 Three 要绘制组成形状的三角形的两面。对于像球体或立方体这样的实体形状，通常没有必要绘制三角形的背面，因为它们都朝向形状内部。不过在我们的例子中，我们正在绘制一些像 PlaneGeometry 和 ShapeGeometry 这样二维的东西，因此没有内部。如果不设置 side: THREE.DoubleSide，当从背面观看时它们会消失。

我应该指出，不设置 side: THREE.DoubleSide 时绘制速度会更快，因此理想情况下我们只在真正需要的材质上设置它，但在这种情况下我们绘制的内容不多，所以没有必要太担心。

让我们创建一个函数 addSolidGeometry，我们传入几何体，它通过 createMaterial 创建随机颜色的材质，并通过 addObject 将其添加到场景中。

function addSolidGeometry(x, y, geometry) {
  const mesh = new THREE.Mesh(geometry, createMaterial());
  addObject(x, y, mesh);
}

现在我们可以将其用于我们创建的大多数基本几何体。例如创建一个盒子

{
  const width = 8;
  const height = 8;
  const depth = 8;
  addSolidGeometry(-2, -2, new THREE.BoxGeometry(width, height, depth));
}

上述模式有一些显著的例外。 最大的例外可能是 TextGeometry。它在生成文本的网格之前需要加载3D字体数据。 这些数据是异步加载的，因此我们需要等待它加载完成才能尝试创建几何体。通过将字体加载 promisify，我们可以使这个过程更容易。 我们创建一个 FontLoader，然后创建一个函数 loadFont，它返回一个 promise，promise 解析后将提供字体。然后我们创建一个 async 函数，名为 doit，并使用 await 加载字体。 最后创建几何体并调用 addObject 将其添加到场景中。

{
  const loader = new FontLoader();
  // promisify font loading
  function loadFont(url) {
    return new Promise((resolve, reject) => {
      loader.load(url, resolve, undefined, reject);
    });
  }

  async function doit() {
    const font = await loadFont('resources/threejs/fonts/helvetiker_regular.typeface.json');  /* threejs.org: url */
    const geometry = new TextGeometry('three.js', {
      font: font,
      size: 3.0,
      depth: .2,
      curveSegments: 12,
      bevelEnabled: true,
      bevelThickness: 0.15,
      bevelSize: .3,
      bevelSegments: 5,
    });
    const mesh = new THREE.Mesh(geometry, createMaterial());
    geometry.computeBoundingBox();
    geometry.boundingBox.getCenter(mesh.position).multiplyScalar(-1);

    const parent = new THREE.Object3D();
    parent.add(mesh);

    addObject(-1, -1, parent);
  }
  doit();
}

还有一个区别。我们希望围绕文本的中心旋转文本，但默认情况下，three.js 创建的文本中心旋转点在左边缘。为了解决这个问题，我们可以让 three.js 计算几何体的边界盒。然后我们可以调用边界盒的 getCenter 方法，并传入我们网格的位置对象。getCenter 会将盒子的中心复制到位置对象中。它还会返回位置对象，因此我们可以调用 multiplyScalar(-1) 来定位整个对象，使其旋转中心位于对象的中心。

如果我们像之前的例子那样直接调用 addSolidGeometry，它会再次设置位置，这是不可行的。所以，在这种情况下，我们创建一个 Object3D，它是 three.js 场景图的标准节点。Mesh 也继承自 Object3D。我们将在另一篇文章中讲解 场景图的工作原理。 目前，只需要知道像 DOM 节点一样，子节点是相对于它们的父节点绘制的。 通过创建一个 Object3D 并将我们的网格设置为它的子节点，我们可以将 Object3D 放置在任意位置，同时仍然保持之前设置的中心偏移。

如果我们不这样做，文本会偏离中心旋转。

其他例外是基于两行的示例，用于 EdgesGeometry 和 WireframeGeometry。它们没有调用 addSolidGeometry，而是调用了 addLineGeometry，效果如下

function addLineGeometry(x, y, geometry) {
  const material = new THREE.LineBasicMaterial({color: 0x000000});
  const mesh = new THREE.LineSegments(geometry, material);
  addObject(x, y, mesh);
}

它创建了一个黑色的 LineBasicMaterial，然后创建一个 LineSegments 对象，它是 Mesh 的包装器，帮助 three 知道你正在渲染线段（每段 2 个点）。

    color: 'red',
    size: 0.2,     // in world units
});
const points = new THREE.Points(geometry, material);
scene.add(points);

如果你希望点的大小不随它们与相机的距离而变化，可以将 sizeAttenuation 设置为 false。

另一个重要要点是，几乎所有形状都有各种设置来控制它们的细分程度。一个很好的例子是球体几何体。球体需要参数来确定周围和上下的划分数量。例如

第一个球体周向分段为 5，高向分段为 3，总共有 15 个分段或 30 个三角形。第二个球体周向分段为 24，高向分段为 10，总共有 240 个分段或 480 个三角形。最后一个球体为 50×50，总共有 2500 个分段或 5000 个三角形。

你需要决定自己需要多少细分。看起来你可能需要较多的分段，但去掉线条和平面着色，我们得到这个

。现在右边那个有5000个三角形的球体，并不明显比中间那个只有480个三角形的球体完全更好。如果你只画几个球体，比如说一张地球地图上的单个地球仪，那么一个10000个三角形的球体也不是坏选择。另一方面，如果你尝试画1000个球体，那么1000个球体乘以每个10000个三角形就是1000万三角形。为了动画流畅，你需要浏览器以每秒60帧绘制，所以你会要求浏览器每秒绘制6亿个三角形。这需要大量的计算。

有时候选择很容易。例如，你也可以选择细分一个平面。

左边的平面有2个三角形。右边的平面有200个三角形。与球体不同，对于大多数平面的使用情况来说，质量几乎没有权衡。你通常只有在预期要以某种方式修改或扭曲平面时才会细分平面。一个盒子也是类似的。

所以，选择适合你情况的即可。你选择的细分越少，运行越顺畅，占用的内存也越少。你需要自己决定对于你的具体情况，正确的权衡是什么。
